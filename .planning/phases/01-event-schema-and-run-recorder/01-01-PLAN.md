# Phase 1 Plan 01: Event schema and run recorder

**Requirements:** EVT-01, EVT-02, EVT-03. State: PROPOSED until verified below.
**Authoring note:** plan written inline (GSD planner/checker agents not used; time-boxed Hack Day). Recorded, not hidden.

## Design (decided)
- Envelope schema `schemas/events/event.schema.json` (JSON Schema 2020-12), per-type payload constraints via if/then.
- `content_id` = sha256 of canonical JSON of {event_type, actor, payload}. Excludes run_id, seq, ts, meta, deps.
  Identical content in two runs has identical content_id: this is what comparison keys on.
- `event_id` (OCCURRENCE_ID) = sha256(run_id | seq | content_id). `run_id` and `phase_id` are separate fields.
- `deps` = declared dependencies (event_ids in the same run). Only declared deps may imply downstream impact.
- `meta` (latency, tokens, etc.) is recorded but not hashed.
- Recorder: append-only JSONL, one event per line, fsync, refuses seq gaps and unknown types.
- Reader verifies: schema, seq continuity, prev_event_id chain, content_id recomputation, event_id recomputation, deps refer to earlier events.
  This proves internal consistency only. It does NOT prove authenticity (no signing) or truth.
- Failures (`failure`) and abstentions (`abstention`) are first-class, states FAILED / NOT_COMPUTED.

## Verify
pytest tests/unit: every event type validates; content_id stable across runs and independent of meta/ts;
tamper detected; failure + abstention roundtrip; unknown type rejected; forward dep rejected.
